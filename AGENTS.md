# AGENTS.md — правила проекта «Шиноман»

## Стек

- Node.js 26.x (`engines.node: ">=26 <27"`), ESM (`"type": "module"`), Windows.
- HTTP-сервер: Express 5 (`src/app.js`, `src/server.js`) на `node:http`.
- Шаблонизатор: Pug 3 (`src/views/`), пока только страница ошибки.
- Данные: встроенный `node:sqlite`; `bookings.sqlite` и `catalog.sqlite` в `.data/` (в git не попадают).
- Тесты: встроенный `node:test`; `tests/unit`, `tests/integration`.
- Legacy-точка входа `server.mjs` — тонкий wrapper над `src/server.js`.

## Команды

```sh
npm install       # установить зависимости из lockfile
npm start         # production/dev-запуск на HOST:PORT
npm run dev       # запуск с node --watch
npm test          # unit + integration (node --test)
node katalog/catalog-store.mjs путь-к-снимку.json   # импорт каталога
```

## Запреты

- Не менять URL, коды ответов и схему `bookings.sqlite` без отдельного этапа и разрешения.
- Не менять поведение booking API: 200/201/400/409/415, валидация, идемпотентность `requestId`, CORS `BOOKING_WEB_ORIGIN`.
- Не добавлять SEO-маршруты, canonical, sitemap, robots до соответствующего этапа.
- Не удалять `katalog/data.json` и таблицу `catalog_snapshot`.
- Не использовать `app.get('*')`: в Express 5 другой синтаксис.
- Не добавлять зависимости без явного разрешения (разрешены только `express@^5`, `pug@^3`).
- Не отдавать через статику `.data`, `src`, `tests`, `migrations`, `package.json`, `.git`, `node_modules`.
- Не выполнять `git reset --hard`, `git checkout --`, `git push`.
- Не вызывать субагентов и не подписывать собственную работу.

## Правила этапов

1. Один этап — один проверяемый инкремент; не начинать следующий этап без команды.
2. Сначала краткий план (10–15 строк), затем сразу реализация.
3. Сохранять работающий legacy-сайт: URL, статусы, данные.
4. Каждый этап заканчивается зелёным `npm test` и живыми проверками затронутых маршрутов.
5. Новые тесты — в `tests/unit` или `tests/integration`; регрессии legacy не удалять.
6. Отчёт этапа — в `docs/stage-reports/NN-slug.md`.
7. Пакет для ревью — в `docs/reviews/NN-review-input.md`.
8. Изменения не коммитить и не пушить без команды.

## Формат отчёта

- Цель этапа и что сделано.
- Список созданных/изменённых/удалённых файлов.
- Команды проверок и их результат (`npm test`, curl/HTTP).
- Принятые решения и отклонения от ожиданий.
- Сомнения, риски, блокеры.
- Явная отметка: следующий этап не начат.

## Правило про SOL

- GPT-6.2 SOL — внешний независимый ревьюер. Из рабочего чата его не вызывают.
- Исполнитель готовит `docs/reviews/NN-review-input.md` с диффом, тестами и вопросами.
- Исполнитель не ставит финальную подпись и не объявляет этап принятым: «готово к ревью SOL» — только при зелёных проверках.
- Замечания SOL исправляются отдельным проходом с повторным прогоном проверок и обновлением review-пакета.
